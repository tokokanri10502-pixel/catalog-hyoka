# 予約カタログ評価

スーパーの予約カタログ（節分・母の日/父の日・土用の丑・ボジョレー・クリスマス・おせち等）を、
社内＋社外がスマホで順位付けし、管理画面で分析する仕組み。

- 回答：QR → 社内/社外を選ぶ → 催事を選ぶ → 総合順位 → 6項目の順位 → ひとこと → 送信（匿名・1端末1催事1回）
- 管理：`#/admin`（パスワード）… 分析 / 催事・社 / 期間・設定 / QRコード / 回答データ（Excel出力）
- 開発：`npm run dev`（ポート5185）。Supabase未設定ならデモモード（架空データ・管理PW `demo`）

## 分析の中身
| | 内容 |
|---|---|
| 総合順位 | 平均順位・ポイント（1位＝社数点…最下位＝1点）・1位票・評価ランク S/A/B/C |
| 項目別 | 社×項目の平均順位ヒートマップ |
| 相関 | 回答者ごとに総合順位と各項目順位のスピアマン順位相関ρ→平均。1位一致率も |
| マトリクス | 影響度ρ × 自社の平均順位 →「優先改善」象限 |
| 改善ポイント | 優先度＝ρ×自社順位の低さ。総合1位（自社1位なら2位）との差 |
| 社内外のズレ | 社×項目の平均順位差、項目ごとのρの差 |
| 項目間相関 | 0.8以上は回答者が区別できていない可能性 |
| 全催事まとめ | 催事×項目のρ、自社の催事横断の強み・弱み、所見 |
| 年ごとの比較 | 同名の催事を年ごとに並べ、自社の総合順位の推移と項目別の前年比（▲改善/▼悪化） |

評価ランク：平均順位を (avg-1)/(社数-1) に換算し 0.2以下=S お手本 / 0.4以下=A 強み / 0.6以下=B 標準 / それ以上=C 課題
（6社なら 2.0位以内=S, 3.0=A, 4.0=B）

## 公開手順（初回のみ）
1. Supabaseで**新規プロジェクト**を作る（book-markers-v2 等の共有プロジェクトは使わない）
2. SQL Editor に `supabase/schema.sql` を貼って Run → 続けて `supabase/set_password.sql` の「ここにパスワード」を書き換えて Run
3. Project Settings → API の URL と publishable(anon) キーを `.github/workflows/deploy.yml` に記入
4. GitHubに新規リポジトリを作り、このフォルダを push。Settings → Pages → Source を「GitHub Actions」に
5. 公開URL`/#/admin` → 催事・社で各催事の社を登録 → 期間・設定で受付期間 → QRコードを印刷
6. 実物カタログに A〜F の記号シールを貼る（管理画面の記号と合わせる）

## 運用メモ
- 未発行：催事ごとに「カタログ発行済み／未発行」を切り替え。未発行は回答画面に「未発行」と出て回答不可（サーバー側でも拒否）。次の年を作ると全催事が未発行で作られる
- 共用タブレット：管理画面「QRコード」の共用タブレット用QR（`#/?kiosk=1`）をタブレットで開くと共用モード。「回答を終えて、次の方へ」で回答者を切り替え（端末IDを作り直す）。操作なし5分で自動リセット。解除は `#/?kiosk=0`
- 年：催事は年ごとに登録し「おせち 2026年」のように表示。翌年は「催事・社」→「次の年を作る」で前年の催事と社をコピー → 「期間・設定」で受付する年と期間を切り替え。回答画面には受付する年の催事だけが出る。過去の年のデータは残り、管理画面右上で年を切り替えて見られる
- 社の入れ替え：催事・社タブで編集。削除した社は過去回答からも集計対象外（残りの社で順位を詰めて計算）
- テスト回答は「回答データ」タブで削除してから本番を始める
- 社内・社外どちらかが10人未満なら分析に「参考値」注記が出る
